# Полигон «Корпоративный мессенджер»

Экзаменационный полигон для 4 команд (4 курс). Формат — 6 часов:
2.5 часа разработки + 2 часа игры на безопасность и производительность
+ 0.5 часа брифинга + 1 час разбора и защиты.

## Что внутри

- `starter/` — заготовка Flask+SQLite, которую получает каждая команда.
- `teams/teamN/` — рабочие копии команд (создаются скриптом).
- `referee/` — автономный судья: SLA-пинг + 7 типов атак.
- `scoreboard/` — веб-табло: http://127.0.0.1:8000
- `docs/` — ТЗ, модель очков, карта уязвимостей (для студентов).
- `scripts/` — вспомогательные скрипты.
- `run_all.py` — запускает всё одной командой.

## Подготовка (один раз)

Установите зависимости referee и scoreboard в общий интерпретатор:

```bash
pip install -r referee/requirements.txt
pip install -r scoreboard/requirements.txt
```

Установите зависимости starter (либо по разу в venv каждой команды, либо
один раз глобально):

```bash
pip install -r starter/requirements.txt
```

Создайте команды:

```bash
python scripts/init_teams.py
```

Скрипт создаст `teams/team1..team4/` как копии `starter/` и пропишет
каждой команде свой `.env` (team_id, порт, секреты).

## Запуск полигона

```bash
python run_all.py
```

Поднимает:

- 4 приложения команд — http://127.0.0.1:5001 .. :5004
- referee (фоном, пишет `referee/scores.json` и `referee/events.json`)
- scoreboard — http://127.0.0.1:8000

Остановить всё — Ctrl+C в том же окне.

## Как устроен экзамен

1. **0:00–0:30.** Брифинг. Раздаёте `docs/*.md`, объясняете правила.
2. **0:30–1:00.** Команды читают спеку и планируют.
3. **1:00–3:30.** Разработка. Каждая команда правит только свой
   `teams/teamN/`.
4. **3:30–3:45.** Заморозка. Вы запускаете `python run_all.py`.
5. **3:45–5:45.** Игра. Referee автоматически проверяет SLA и атакует.
   Scoreboard обновляется в реальном времени.
6. **5:45–6:00.** Стоп-игра, финальный подсчёт.
7. **6:00–7:00.** Разбор: смотрите `referee/events.json` и объясняете
   командам, где и что они упустили.

## Что делают студенты

- Читают `docs/features.md` — 8 эндпоинтов, которые нужно реализовать.
- Читают `docs/vulnerabilities.md` — 7 уязвимостей, которые referee будет
  искать.
- Читают `docs/scoring.md` — как начисляются очки.
- Пишут код в своём `teams/teamN/`.
- За 30 минут до конца — коммитят всё, что успели.

## Что делаете вы

- **До экзамена:** запускаете `python scripts/init_teams.py`, проверяете,
  что все 4 команды поднимаются и отвечают на `/api/v1/health`.
- **На экзамене:** раздаёте документы, запускаете `python run_all.py`,
  наблюдаете за scoreboard.
- **В конце:** открываете `referee/events.json` — там полная история
  событий. Используете её для разбора и выставления оценки.

## Как остановить и перезапустить

- **Остановить:** Ctrl+C в окне `run_all.py`.
- **Сбросить очки:** удалите `referee/scores.json` и `referee/events.json`.
- **Пересоздать команды:** удалите `teams/teamN/` и снова запустите
  `python scripts/init_teams.py`.

## Что НЕ используется

Специально, чтобы не усложнять:

- никакого Docker;
- никакого gunicorn или uwsgi — только встроенный `flask run`;
- никаких брокеров, Redis, Celery;
- никаких внешних БД — только SQLite;
- никакого фронтенд-фреймворка — только Jinja-шаблоны.
